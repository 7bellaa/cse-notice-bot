## 1. P0-1 · 이벤트 라벨 가독성 개선

### 1.1 배경
현재 셀 내 이벤트 라벨은 1줄로 `text-overflow: ellipsis` 처리되어 핵심 키워드(예: "AI Booster 모집")가 잘려 나타난다. 사용자는 셀을 클릭해서 외부 공지로 이동하기 전까지 일정의 성격을 파악하기 어렵다.

### 1.2 목표
- 셀 안에서 일정의 의미를 1초 내 식별 가능.
- 색상에 의존하지 않고 텍스트 정보로도 카테고리 인지 가능.

### 1.3 범위
- 월 뷰 셀 내부 이벤트 칩.
- 호버/포커스 시 노출되는 풀 텍스트 툴팁.
- 목록 뷰는 본 항목 범위 외(별도 OK).

### 1.4 구현 상세

**(a) 라벨 멀티라인**
```css
.event-chip__title {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
  word-break: keep-all;
  line-height: 1.25;
  font-size: 12px;
}
```
- 한 셀당 최대 표시 이벤트: 3개. 초과 시 `+N건 더보기` 푸터(클릭 시 해당 날짜 일별 패널 오픈).

**(b) 카테고리 칩 + 텍스트 이중 인코딩**
```html
<a class="event-chip" data-category="scholarship">
  <span class="chip-tag">장학</span>
  <span class="event-chip__title">2026.1학기 국가근로장학금 …</span>
</a>
```
- `data-category` 값: `scholarship | academic | career | extracurricular | notice`.
- `chip-tag`는 카테고리별 배경색, 흰색 텍스트, 10px, padding 2x6.

**(c) 접근성 툴팁**
- 호버 + 포커스(키보드 Tab) 시 250ms 지연 후 표시.
- 마크업: `role="tooltip"`, `aria-describedby`로 이벤트 링크와 연결.
- ESC 또는 blur 시 닫힘.
- 모바일 터치에서는 비활성(롱프레스 X) — 모바일은 목록 뷰가 기본이므로 불필요.

### 1.5 수용 기준 (Acceptance Criteria)
- [ ] 1280px 기준 모든 이벤트 라벨에서 첫 2줄의 정보로 카테고리/주제 식별이 가능하다.
- [ ] 카테고리 칩이 텍스트(장학/학업/졸업/비교과/공지)로 함께 표시된다.
- [ ] 셀당 4개 이상 이벤트가 있을 때 `+N건 더보기`가 나타나고, 클릭 시 해당 날짜 패널이 열린다.
- [ ] 키보드 Tab으로 이벤트에 포커스했을 때 풀 제목 툴팁이 보인다.
- [ ] 툴팁은 ESC로 닫히며 스크린리더에서 풀 제목을 읽어준다.

## 2. P0-2 · 범례(Legend) 상단 이동 및 토글화

### 2.1 배경
현재 범례는 캘린더 하단에 위치하여 첫 화면에 보이지 않는다. 색상 인코딩이 무엇을 의미하는지 모른 채 일정을 스캔하게 된다.

### 2.2 목표
- 첫 페인트(LCP 직후) 시점에 범례가 보이도록 한다.
- 사용자가 원할 경우 접어 둘 수 있어야 한다(공간 절약).

### 2.3 범위
- 헤더(타이틀 영역)와 캘린더 그리드 사이에 범례 바 신규 배치.
- 기존 하단 범례는 제거.

### 2.4 구현 상세

**(a) 위치/구조**
```
[Header: 타이틀 + 요약 + GitHub]
[Toolbar: ← → 오늘  |  YYYY년 M월  |  월 / 목록]
[LegendBar: 🟪 장학  🟢 학업  🩷 졸업  🟧 비교과  ⚪ 공지  | ★ 중요  | (접기 ▲)]
[Calendar Grid]
```

**(b) 토글 동작**
- 기본 상태: 펼침(`expanded`).
- 사용자 액션으로 접으면 `localStorage["legend.collapsed"] = "true"`로 저장.
- 접힌 상태는 `legend-bar--collapsed` 클래스로 높이 0, 토글 버튼만 노출.

**(c) 인터랙티브 힌트 (P0 범위)**
- 각 범례 항목은 시각적으로 클릭 가능해 보이지 않게(`cursor: default`).
- 단, `aria-label`과 `title`로 카테고리 설명을 제공.
- **카테고리 필터링 동작은 P1에서 도입** — 본 PR에서는 마크업만 미리 구조화.

### 2.5 수용 기준
- [ ] 캘린더 페이지 진입 시 viewport 첫 화면에 범례가 노출된다(1280×900 기준).
- [ ] 하단 범례는 제거되어 중복 표시되지 않는다.
- [ ] 토글 상태가 새로고침 후에도 유지된다.
- [ ] 접힘 상태에서도 토글 버튼은 항상 보이며 키보드 포커스 가능.

### 2.6 테스트 케이스
| TC | 시나리오 | 기대 결과 |
|---|---|---|
| TC1 | 초기 진입 | 범례 상단 노출, 캘린더 그리드 위에 위치 |
| TC2 | 접기 클릭 후 새로고침 | 접힘 상태 유지 |
| TC3 | 키보드 Tab 순서 확인 | Header → Toolbar → Legend Toggle → Calendar |

## 3. P0-3 · 모바일 반응형 대응

### 3.1 배경
현재 ≤ 480px 환경에서 7열 그리드가 그대로 유지되어 가로 스크롤이 발생하고, 헤더 영역도 가로로 펼쳐져 콘텐츠가 거의 식별 불가능하다.

### 3.2 목표
- 360 ~ 768px 환경에서 가로 스크롤 0.
- 모바일 사용자가 "다가오는 일정"을 1탭 내에 확인 가능.

### 3.3 범위
- 전체 페이지 레이아웃 (헤더/툴바/범례/뷰).
- 기본 뷰 자동 전환 로직.

### 3.4 구현 상세

**(a) 브레이크포인트**
```
sm:  ≤ 480px   → 1열 스택, 목록 뷰 강제
md:  481–768px → 2열 헤더, 목록 뷰 기본 / 월 뷰 토글 가능
lg:  ≥ 769px   → 현재 데스크톱 레이아웃
```

**(b) 모바일 레이아웃 규칙 (≤ 768px)**
- 헤더: 타이틀 / 서브카피 / 우측 메타(0건, GitHub) 세로 스택.
- 툴바: 한 줄 → 두 줄. 위: `< 오늘 >`, 아래: 월 텍스트 + 뷰 토글.
- 범례: 가로 스크롤 가능한 chips row (`overflow-x: auto; scroll-snap`).
- 뷰: 페이지 진입 시 `viewport < 768px`이면 자동으로 `list` 뷰로 전환. 단, 사용자가 명시적으로 `month`를 선택하면 `sessionStorage["view.preference"]` 우선.

**(c) 목록 뷰 모바일 최적화**
- 날짜 헤더는 sticky.
- 각 이벤트 row: 카테고리 칩 + 제목 2줄 + 외부 링크 아이콘.
- 터치 타깃 최소 44×44pt 보장.

### 3.5 수용 기준
- [ ] 360px / 390px / 414px / 768px 4개 폭에서 가로 스크롤이 발생하지 않는다.
- [ ] 360px 진입 시 기본 뷰가 "목록"이다.
- [ ] 사용자가 모바일에서 "월" 뷰를 선택하면 새로고침 후에도 동일 세션 동안 월 뷰가 유지된다.
- [ ] 헤더 텍스트가 잘리거나 겹치지 않는다.

### 3.6 테스트 케이스
| TC | 디바이스/폭 | 기대 결과 |
|---|---|---|
| TC1 | iPhone SE (375px) | 목록 뷰, 가로 스크롤 없음 |
| TC2 | iPhone 14 (390px) | 헤더 3행 스택, 범례 chip 가로 스크롤 동작 |
| TC3 | iPad mini portrait (768px) | 목록 뷰 기본, 월 뷰 토글 정상 |
| TC4 | 모바일에서 월 뷰 선택 후 새로고침 | 같은 세션 동안 월 뷰 유지 |

## 4. P0-4 · 명도 대비 (WCAG 2.1 AA) 보정

### 4.1 배경
- "오늘" 버튼이 활성 상태임에도 비활성처럼 흐릿함.
- 인접 달 날짜(예: 4/26, 6/1) 텍스트가 거의 식별되지 않음.
- 헤더 메타("0건 마감 예정")의 그레이가 흰 배경 대비 약 3.0:1로 추정되어 AA 기준 4.5:1 미달.

### 4.2 목표
- 본문 텍스트는 4.5:1 이상, 비활성/보조 텍스트는 3:1 이상.
- 색맹/저시력 사용자도 카테고리 정보 식별 가능.

### 4.3 범위
- 디자인 토큰(`tokens.css` 또는 `tailwind.config.js` 색상 팔레트).
- 영향 컴포넌트: 헤더 메타, 툴바 "오늘" 버튼, 인접 달 날짜, 범례 라벨, 카테고리 칩 텍스트.

### 4.4 구현 상세

**(a) 토큰 변경안**
| 토큰 | Before (추정) | After | 대비 |
|---|---|---|---|
| `--text-muted` | `#B8B8B8` | `#6B7280` | 4.6:1 |
| `--text-disabled` (다른 달 날짜) | `#E5E5E5` | `#9CA3AF` | 3.1:1 |
| `--btn-today-fg` | `#C7C7C7` | `#374151` | 9.1:1 |
| `--header-meta-fg` | `#A0A0A0` | `#4B5563` | 7.0:1 |

**(b) 카테고리 칩 텍스트**
- 모든 칩 배경 위 텍스트는 흰색(`#FFFFFF`) 사용 시 배경과 4.5:1 만족 여부 검증.
- 미달 색상(노랑 계열 등)은 배경을 0.5단계 어둡게 보정.

**(c) 색상 보조 패턴 (옵션, 작업량 적을 시 포함)**
- ★ 중요 일정: 별 아이콘 + 외곽선(`outline: 1px solid currentColor`).
- 카테고리 칩: 텍스트(장학/학업…)로 의미 중복 인코딩.

### 4.5 수용 기준
- [ ] axe-core 자동 검사에서 contrast 위반 0건.
- [ ] "오늘" 버튼이 현재 달에서도 명확히 활성으로 인지된다.
- [ ] 다른 달 날짜는 식별 가능하되 현재 달과 시각적 위계가 유지된다.

### 4.6 테스트 케이스
| TC | 도구/방법 | 기대 결과 |
|---|---|---|
| TC1 | axe DevTools 풀 페이지 스캔 | contrast 카테고리 violations = 0 |
| TC2 | Chrome DevTools Rendering → 색맹 시뮬레이션(Protanopia, Deuteranopia) | 카테고리 구분이 텍스트 기준으로 가능 |
| TC3 | 디자이너 수동 리뷰 | 시각적 위계(이번 달 > 인접 달)가 보존됨 |

## 5. 공통 요구사항

### 5.1 접근성
- 모든 상호작용 요소는 `:focus-visible` 스타일을 제공한다.
- 캘린더 그리드는 `role="grid"`, 셀은 `role="gridcell"` + `aria-label="YYYY년 M월 D일, 일정 N건"`.
- 키보드 포커스 순서: Header → Toolbar → Legend → Grid(좌→우, 위→아래).

### 5.2 브라우저/디바이스 지원
- Chrome / Safari / Edge 최근 2버전.
- iOS Safari 16+, Android Chrome 최근 2버전.

### 5.3 성능
- LCP < 2.5s (기존 대비 회귀 없음).
- 추가 JS 번들 증가 ≤ 8KB gzip.
- 신규 이미지 자원 추가 금지(아이콘은 인라인 SVG).

### 5.4 비범위 (Out of Scope)
- 카테고리 필터링 동작(P1).
- 검색창(P1).
- iCal 구독(P2).

### 5.5 의존성
- 새 라이브러리 도입 없음. 기존 CSS 시스템과 컴포넌트 구조 재사용.
- 디자인 토큰 변경은 Tailwind 사용 시 `tailwind.config.js`, 순수 CSS 사용 시 `:root` 변수.

### 5.6 일정 (5영업일 가이드)
| Day | 작업 |
|---|---|
| D1 | 디자인 토큰 정비(P0-4), 범례 상단 배치(P0-2) |
| D2 | 이벤트 라벨 멀티라인 + 카테고리 칩(P0-1) |
| D3 | 툴팁 + 키보드 포커스(P0-1), `+N건 더보기` 패널 |
| D4 | 모바일 레이아웃 + 자동 뷰 전환(P0-3) |
| D5 | axe-core 검사, QA, 회귀 수정, 릴리스 노트 작성 |
